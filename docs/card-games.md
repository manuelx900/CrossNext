# Card games

Solitaire and Hearts use landscape orientation and restore portrait on exit. They share CardArt and CardPanels. The one-bit illustrations under `assets_local/reference_art/` come from the supplied design references; regenerate their constexpr header with `tools_local/reference_art/generate.py`. Image conversion is a development dependency only. Runtime drawing adds no heap allocation or second framebuffer.

Both How to Play guides support swiping left or up for the next page and right or down for the previous page. Horizontal swipes can start at either side edge; the existing top and bottom system gestures retain priority. The first and last pages do not wrap. Header Back and the physical Back action return to the game menu; board gestures and saved games are unchanged. The Spanish deck guide calls the J card Jota (J).

Solitaire has menu, new-deal, settings and two help pages. Undo and Menu are in the board header. `/.crosspoint/solitaire.opts` stores version 1 plus three boolean bytes: default draw-three, confirm replacement and show move count. Existing game/result files retain their format. Foundation cards are displayed by suit, including old saves whose underlying piles have a different order. Draw mode is selected for a new deal and never changes the current board.

Hearts has passing, play and round/match result screens. Preferences (`/.crosspoint/hearts.opts`) are version 1 plus difficulty index (Easy/Normal/Expert), short-game, confirm replacement and highlight-valid flags. Default limits are 50 or 100. Easy uses Rookie policy, Expert uses Sharp policy, and Normal chooses between those public-information policies on each decision. No policy sees another hand.

Hearts saves use version 2: the unchanged Game payload followed by active Skill (Rookie=0, Sharp=1, Normal=2) and short-game byte. Version 1 saves load with their previous skill preference and a 100-point limit. Active rules survive re-entry independently of the defaults for the next game. Legacy placement results keep their meaning; `hearts.best` stores the lowest completed human score as two little-endian bytes. No existing placement is reinterpreted as a score.

Host and browser verification cover menu/form navigation, legal card routes, hand selection, both draw modes, both target scores, Normal policy legality, outlines versus filled suits, help pages and the chess completion trophy. Before hardware use, verify landscape touch mapping, exit orientation, undo, long tableau columns, three-card passing, invalid plays, round/match completion and SD write failure behaviour. Retired Jaipur/Slitherlink/Hashi Home shortcut targets are removed when decoding the existing Home menu configuration; other labels and shortcuts remain intact. Firmware/device checks remain pending until the simulator design is approved.
