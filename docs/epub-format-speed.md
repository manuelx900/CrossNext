# EPUB formatting work reuse

Text adjustments start after the current touch or adjustment key is released. Holding a control coalesces its changes. The reader keeps the existing page while computing the correct replacement; it does not render a lower-quality draft. AA, images, CSS, line breaking and pagination keep their normal rendering paths. Selecting a bounded value already in effect does no work. A raster-only change such as AA can reuse the composed section.

Format recomposition runs in the existing render worker in cooperative slices, targeting one emitted page or eight milliseconds between parser steps. A callback can overrun this interval. Font loading, initial source extraction, CSS hydration and a single complex paragraph/image remain synchronous operations. Exact pagination to a later content anchor still requires composing the preceding part of the chapter. This does not promise instant reflow for every EPUB or a measured advantage over closed firmware.

## Ownership and bounds

The reader owns its Section and optional caches; no task, framebuffer, persistent format, image reduction or panel waveform is added. The existing stored-BW slot backs the text controls, and is released before the full-quality replacement page needs it. A new request discards an unfinished format build without draining its spool. Existing committed layout profiles survive. An event-replay failure switches to XHTML with the same format-build policy.

The session paragraph arena keeps its 128 KiB payload and admits up to 512 entries in a combined allocation capped at 192 KiB PSRAM. Admission stops when full; existing entries remain useful on the next sequential pass. A chapter path change resets admission. Exact raw callback bytes, styles and semantic flags are compared before restoring normalized tokens. Large, annotated and unsupported paragraphs retain ordinary parsing. A new chapter with the same text cannot exhaust the old chapter's admission slots.

One parser can lease the reader's word, prefix and hyphen metrics plus paragraph-gap workspace (the existing caps: 48 + 6 + 2 + 16 KiB PSRAM). A concurrent preparation parser uses private scratch. Identity includes font content, emphasis, all style bits, spacing and language as appropriate. Low PSRAM releases the shared metrics at the next acquisition. Reader exit releases the session cache; parser cleanup defers release while borrowed.

The EPUB's CSS parser can retain its existing bounded rule store (12 KiB index, 32 KiB selector pool and approximately 26 KiB styles). Reuse requires matching nonzero HAL resource/media revisions and sufficient memory; otherwise rules reload normally. Only exact canonical EPUB HTML, section and event cache writes use the HAL's explicit derived-cache APIs. Ordinary writes and unknown paths still invalidate resources. Per-book text records are reading state. A shared/global settings save conservatively invalidates resource caches, so CSS may reload on the next adjustment in that mode. Host simulator revisions are zero and disable this reuse.

A format build may reserve an additional 256 KiB PSRAM spool if at least 2 MiB headroom remains. It still writes the small incomplete header on the SD. Serialized page payloads stay in memory until the correct page has been presented, and the ordinary Page decoder reads that same byte stream directly. Persistence starts after at least 200 ms without a text adjustment, with at most 8 KiB of spool data per idle callback. Settings/progress saves use this idle path too. At the half-capacity watermark, parser-slice boundaries switch to stepped 8 KiB draining before continuing with ordinary SD writes. An exceptional single callback larger than the remaining spool capacity drains synchronously. Low memory also falls back to normal SD writes without changing quality or the cache format. Cancellation removes the incomplete file; exit and sleep flush the captured presented progress and pending preferences. Section destruction discards a format build and suspends an ordinary build. A failed settings save is logged and retried on the next adjustment or exit, rather than spinning on a failing SD card.

## Verification

Run `host-tests/epub-format/run.py` (with CROSSNEXT_GTEST set to a GTest checkout), `host-tests/reader-io/run.py --only chapter-layout`, `host-tests/reader-io/run.py --small`, and `host-tests/reader-next/run.py --only hal-policy` / `--only build-slices`. On Windows these focused runners use the local Emscripten toolchain. The chapter suite compares full page bytes and source anchors with caches disabled versus successive warm spacing/indent/tracking changes. This is host equivalence, not a physical panel comparison or device timing.

On X4 Pro, test a plain novel, a long single-chapter EPUB, embedded CSS, ruby/links/footnotes and illustrated pages. Keep the book, font, AA, SD card and position fixed for comparisons. Try isolated and rapid font/size/spacing/margin changes, minimum/maximum controls, AA alone, closing the panel mid-composition, returning Home, opening a child activity, sleep and reopen. Repeat in both orientations and night mode. The replacement must preserve the text anchor, exact content, image detail and final AA. Text controls must remain usable between parser steps; page turns wait for the correct replacement page. Watch serial performance traces for operation time and SD I/O; verify free/internal/PSRAM memory recovers on exit. Missing text, changed line order, stale settings after reopening, a blank restored panel or unbounded cache growth is a failure. Do not erase all caches merely to compare warm adjustments; use a separate SD copy for cold-cache tests.
